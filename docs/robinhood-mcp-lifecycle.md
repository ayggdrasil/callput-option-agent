# Robinhood Chain Account trading through MCP

Connect to `https://mcp.callput.app/api/mcp?network=robinhood`. In `callput_get_network_info`, check chain 4663, USDG with six decimals, and `account_workflow.configured`. Read `callput://account/workflow` for exact field names and the signer protocol. The MCP never receives private keys. An external agent needs its own owner signer and a distinct device signer; the hosted browser approval page is optional and must be provisioned before being advertised.

| Task | MCP calls |
| --- | --- |
| Resolve or create a trading account | `callput_account_resolve`, `callput_workflow_start`, `callput_wallet_connect` with the two public addresses, then `action_prepare(login)` and `action_prepare(create)`. Sponsored create uses `action_submit` with `result: {}`; wait for confirmation before depositing. |
| Deposit USDG | Set `deposit_amount_raw` and `max_deposit_gas_wei` in the workflow. Prepare `deposit`, have the owner broadcast the exact transfer once, and submit its existing transaction hash. The owner pays native gas. |
| Open a spread | Prepare `register` and approve the exact bounded grant with the owner. Select a Buy/Sell Call/Put spread on one asset. Use `callput_scan_spreads` or `callput_get_option_chains` for legs. Prepare `open` with both leg IDs, size, minimum fill ratio and a maximum raw collateral amount. The device signs the resulting intent. |
| Track a submitted order | Call `callput_action_status` for the same action. Check relay admission, canonical receipt and PositionManager request key, then finalized execution or keeper cancellation. On Robinhood, the PositionManager restricts cancellation to its own execution path; users cannot manually cancel its request. |
| Close an unexpired position | Read `callput_portfolio_summary` with the actual account address; each position carries its exact `token_id`, `size_raw`, strategy and lifecycle. Prepare `close` with `option_token_id`, `size_raw` and an explicit positive `min_amount_out_raw`. If the original grant is unavailable, start a new workflow for the same account, underlying and strategy with `session_mode: "close_only"`, a zero open cap, and fresh owner approval. |
| Settle an expired position | Prepare `settle` for one held expired `option_token_id`. Use the saved device binding or a valid owner login; the latter uses `result: {}`. The settlement recipient is fixed to the account. |
| Withdraw available collateral | Prepare `withdraw` with raw USDG amount and optional recipient (default: owner). The owner signs the exact token, amount, recipient, epoch, nonce and deadline. Check the finalized transfer before treating it as completed. |
| Turn off a device or recover unused authority | Use `callput_session_revoke` for the selected session and `callput_workflow_recover` only with finalized proof as described in the [relay runbook](robinhood-relay-recovery.md). |

Use the `callput_` prefix for the abbreviated action tools in the table. Parse each `wallet_request` rather than constructing calldata yourself. Before asking the signer, call `callput_action_begin` and require `wallet_request_may_execute: true`. Use the owner or device specified in `signer`; submit the exact return value as `result.signature` or `result.transaction_hash`. A null wallet request with `result_kind: "empty_object"` needs no new signature. Keep workflow IDs and any signatures out of shared logs. An unclear result calls for observing the original action, never generating a new one to force it through.

Robinhood's Account contract permits four two-leg spread strategies. Vanilla options or a single authorization for an atomic trade with three or more legs are outside the Account protocol. Base direct-wallet tools are a separate route. Availability also depends on the live market feed and relay admission. Referral setup and liquidity provider operations are outside the options order lifecycle. The account workflow is verified using disposable signers and a mock chain/relay, without placing a production order.
