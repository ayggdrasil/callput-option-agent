CallPut MCP

Use your existing wallet

Connect the selected Robinhood or GIWA MCP endpoint. Ask your agent to discover the account workflow tools. Your wallet holds the owner key; a separate browser device key signs only within the permission you approve.

  1. Call callput_get_network_info. Check the network, collateral, account deployment and account_workflow.configured.
  2. Call callput_account_resolve with the owner and sub-index. Existing accounts are resolved across approved factory origins.
  3. Call callput_workflow_start with the owner, selected underlying_asset and strategy, exact authorized deposit amount, total trade cap and separate deposit gas cap. Amounts are raw integers; USDG/USDC use 6 decimals. A raw trade cap of 100000 means 0.1 collateral units.
  4. Open the returned wallet approval link on the selected CallPut app. Connect the existing wallet. The browser creates an encrypted device key and gives the MCP only its public address.
  5. Follow next_actions: login → create if needed → deposit if needed → register trading permission. Review and approve each request in the wallet page.
  6. Once session_ready, prepare the selected spread. The device signs a bounded intent, and the protocol relay sponsors native execution.
  7. Observe the original action until receipt provenance, keeper execution and position change are verified. trade_executed is distinct from a submitted or included transaction.

Fees and recovery

A direct deposit is an ERC20 transfer from the owner wallet and requires owner-paid gas. Trading native fees are sponsored. These are separate permissions and budgets. The first release supports a hard total deposit gas cap on Robinhood Nitro; GIWA direct deposits fail closed because the additional OP L1 fee cannot be bounded by the EOA transaction fields. Funded GIWA accounts can use the session route.

Never repeat an unknown transfer. Submit its existing hash or explicitly recover the same fixed nonce. Never replace an unknown signed order with a new grant. Finalized unused-session recovery requires an archive-capable tracking RPC; an unavailable proof keeps the budget reserved.

Availability

The operator must configure encrypted persistent workflow storage and publish the wallet approval route on each app. If storage is absent, tools return persistent_workflow_store_required. Installing code alone does not prove an operational trade or wallet connection. Read supported_open_underlyings and supported_open_strategies from MCP network info. Each 10-minute grant authorizes one selected market and strategy, one open and one close. The four strategies are BuyCallSpread, SellCallSpread, BuyPutSpread and SellPutSpread. Closing, settlement and owner-signed session revocation have separate prepared actions.

Protect the private workflow link. Do not send a seed phrase, private key or keystore password to an agent or the hosted MCP. Keep browser storage while its trading session is active.

Local encrypted keystore option

If the app-origin approval page is unavailable, an external signer can use the exact prepared MCP requests. For a funded Robinhood account, the optional local signer runtime and SHA-256 checksum provide a Node 22+ client. Its README explains installation, private workflow storage and the hidden local password prompt. It supports one selected spread with a total 0.1 USDG cap, disables deposits and owner transactions, keeps device keys and original signatures encrypted locally, and never releases an old budget automatically.

Extract into a private directory and run npm ci --omit=dev --ignore-scripts. Save your MCP workflow-start result privately as described in the README, run node scripts/run-account-workflow.mjs --check, then run it without --check in your own Terminal. Never send the keystore password to a chat or the MCP. This local option does not make an undeployed browser page available.
